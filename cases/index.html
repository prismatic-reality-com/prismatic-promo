Methodology

Each case in this collection follows a uniform Due Diligence pipeline. A case is not a static report — it is a live analytical workspace that combines OSINT-grade evidence collection with interactive visualization tools designed for desk research, board presentations, and adversarial review.

What every case contains

  • Subject metadata — IČO, legal form, registered address, statutory representatives, ownership structure
  • Network graph — clickable force-directed visualization with cluster halos, depth-based filtering, betweenness centrality scoring, shortest-path queries between any two entities
  • Risk matrix — multi-dimensional radar (regulatory, financial, reputational, market, capacity, conflicts of interest, specialization, international applicability)
  • Comparative shortlist — peer entities benchmarked across the same dimensions
  • Evidence chains — every claim links back to a source document or judicial record (no claim left behind, NCLB pillar)
  • Communications templates — RFP questionnaires, engagement letters, conflict matrices, response templates ready for client use

Doctrine governing these investigations

All cases are produced under the AIAD-DD doctrine — a 19-pillar quality framework enforced via pre-commit hooks and CI gates. The doctrine demands: zero-error runtime operations (ZERO), security enforcement absolute lock (SEAL), no-mercy/no-doubts validation (NMND), no-claim-left-behind evidence (NCLB), and Czech-language excellence (CZE) for all narrative content.

Adding a new case

The cases listing is fully data-driven. There is no template editing required to publish a new case:

  1. Drop the case directory at cases/<slug>/ in the repo root (with index.html + manifest.json)
  2. Run ./scripts/sync-cases-to-promo.sh to mirror it into sites/promo/static/cases/<slug>/
  3. Append the slug to sites/promo/static/cases/index.yaml

The card on this page is rendered automatically from the manifest's display: block (headline, tagline, risk_grade, color, entity_count, graph_depth) with sensible fallbacks to root manifest fields. Each case directory is also exposed at /cases/<slug>/index.html as a standalone offline-capable artifact.

Visual & interaction conventions

Every case dashboard follows the same DRY conventions:

  • A floating "← Prismatic Cases" pill in the top-left corner navigates back to this listing (single source: /cases/_shared/promo-bridge.js)
  • Network graphs use the same cluster color palette across cases for visual consistency
  • Keyboard shortcuts are uniform: / = search, F = focus mode, R = reset, Esc = deselect, ←/→ = walk neighbours
  • Selection state is shareable via URL hash (e.g. #sel=AK&focus=1) — link to a specific entity in any case
